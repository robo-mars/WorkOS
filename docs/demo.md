# Five-minute interview demo

1. **Product (30 seconds).** Open the assistant. Explain that a workplace task often spans booking, IT, people, and policy systems. Show the single conversation entry point and the local-demo label.
2. **Multi-step execution (60 seconds).** Use the first-day workflow card. Expand workflow details: show the plan, specialist assignments, actual tool results, reservation ID, ticket ID, and cited onboarding policy. Explain the no-key planner versus the configurable remote provider.
3. **Approval (45 seconds).** Ask “Request Dubai floor 3 access for onboarding.” Show the exact building, floor, and reason before approving. Point out that the outcome is submitted, not access granted. Open the activity drawer to inspect the actor/timestamped decision.
4. **Memory (30 seconds).** Save a preferred office and zone. Start a new conversation and book without specifying them. Contrast these explicit preferences with seven-day workflow context.
5. **Failure (60 seconds).** Follow `failure-recovery.md` to stop booking, preserve an independent IT action, and retry unfinished steps after restoring the server.
6. **Engineering (45 seconds).** Open the graph implementation and MCP server schemas. Run `make test` and `make eval`. Explain the bounds of the reported metrics and show the per-case results.
7. **Trade-offs (30 seconds).** Explain local simulators, scoped execution agents, simple vector retrieval, SSO as a production extension, and why Redis was omitted.
