# Evaluation methodology

Run `make eval`. The harness loads `evals/scenarios.yaml`, fixes the planner date to 2026-10-07, creates a fresh in-memory database per scenario, seeds any required owned ticket/reservation, and executes the actual LangGraph runtime. Its test-only router uses schemas generated by the real MCP server functions but executes the same simulator domain in-process. No model API or corporate account is involved.

Each case declares ordered expected tools, optional argument assertions, required approval behavior, expected final state, business outcomes, optional cited sources, explicit approval/rejection, and optional injected failures. Outcomes are checked against persisted records, not only assistant prose. Rejected/pending access cases require zero access submissions. Multi-step outages require the independent ticket to survive.

## Metrics

- Task success: exact final status, exact tool sequence, checked arguments, expected sources, business outcomes, and approval checks all pass.
- Tool selection: exact ordered sequence, not a fuzzy keyword match.
- Argument accuracy: per-case agreement with explicitly listed fixture arguments. Only cases with argument assertions enter this metric’s denominator; the report includes the count.
- Retrieval correctness: expected filenames appear among top-three retrieved sources, measured only over cases with source expectations. This is recall-at-three, not answer entailment or ranking quality.
- Unnecessary calls: planned tools absent from the fixture's expected tool set. Retries are separate audit events, not counted as extra planned tools.
- Latency: wall time across graph execution, schema loading, local persistence, and injected retries. It does not measure network/model latency.
- Cost/tokens: zero in deterministic mode. Remote provider usage is captured in workflow state; model prices are not inferred or fabricated.
- Failure handling: expected recovery or safe partial completion on the two injected-failure cases. A sustained outage succeeding as a partial task is not restored availability.
- Approval compliance: expected gate was reached; no sensitive operation occurred before decision.

The checked-in results measured 45/45 passing. This result is specific to a small, development-authored regression set and a deterministic planner designed for those intents. It does not establish general natural-language accuracy. Add held-out paraphrases, adversarial/negative cases, multiple office time zones, and real model evaluations before quoting model performance.

The included baseline retains only the first tool of the plan and has no approval handling. It is a deliberately weak structural baseline, reported as `single_tool_baseline_plan_match`. It is not a prompt-only LLM baseline or evidence that LangGraph increases model intelligence.

Transport/authentication are independently exercised by the real-protocol smoke test and gateway tests. Tests for malformed provider output/fallback use HTTP mocks; live provider and cost benchmarking are intentionally not asserted without credentials and actual measurements.
